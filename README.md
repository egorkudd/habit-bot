# habit-bot

Telegram-бот «Дневник привычек»: питание, зарядка, тренировки и свои привычки.
Требования, архитектура, диаграммы и ход разработки — в папке [`docs/`](docs/README.md);
правила работы над репозиторием — в [`CLAUDE.md`](CLAUDE.md).

Код появляется по частям через pull request (план — раздел 8.1 требований). Готовы:

- **часть 1** — каркас, проверка настроек, база и миграции, каталог ошибок, оповещения администратору, Docker
  и сценарии GitHub Actions, регистрация администратора по `ADMIN_TG_IDS`;
- **часть 2** — каркас диалогов: разбор чисел («77,5» = «77.5»), времени («5:45», «28.40») и дат с понятными
  подсказками, «✕ Отмена» / «отмена» / `/cancel`, сброс незаконченного ввода через 15 минут, «Это меню устарело»,
  отказ на чужие кнопки, главное меню и «Ещё» (разделы пока отвечают «скоро»);
- **часть 3** — регистрация и профиль: приглашения («☰ Ещё» → «🛠 Админ» → «🎟 Приглашения»), анкета из 12 шагов
  с «← Назад», город (кнопки, синонимы, поиск Open-Meteo), расчёт КБЖУ, цели с датой начала и историей,
  «⚙️ Настройки» → профиль с пересчётом, цели вручную, удаление аккаунта.

Команды бота: `/start` — главное меню, `/cancel` — отменить ввод, `/check` — проверка ввода чисел, времени и дат
в три шага (ничего не записывает; нужна, пока разделов нет).

## Как это устроено

- `habit_bot/kernel/` — ядро: настройки, база, пользователи и способы входа, ошибки, логи, реестры модулей и каналов,
  фоновые задачи; `kernel/domain/` — чистые функции разбора и формата чисел, времени и дат.
- `habit_bot/platform/` — общие сервисы (сейчас — оповещения администратору со склейкой за час).
- `habit_bot/channels/telegram/` — всё, что знает про aiogram: `dialogs/` — состояния ввода в базе и сброс
  по бездействию, `ui/` — меню, «Ещё», проверка кнопок.
- `habit_bot/modules/` — функции продукта; сейчас модуль `users` (вход и роли).
- `deploy/` — скрипты для сервера, `.github/workflows/` — сценарии, `scripts/` — помощники CI.

Логика не зависит от Telegram: это проверяет import-linter на шаге «1. Линтер».

## Первый запуск (для владельца)

1. Арендовать VPS с Ubuntu 24.04 (раздел 7.1) и создать бота у @BotFather.
2. Создать ключ выкладки: `ssh-keygen -t ed25519 -f deploy_key` (пароль ключа — пустой).
3. Внести секреты: Settings → Secrets and variables → Actions.

   | Секрет | Что это |
   |---|---|
   | `SERVER_HOST` | IP-адрес VPS |
   | `SERVER_ROOT_PASSWORD` | Пароль root — только для первой настройки, потом удалить |
   | `DEPLOY_SSH_KEY` / `DEPLOY_SSH_PUBLIC_KEY` | Содержимое `deploy_key` и `deploy_key.pub` |
   | `BOT_TOKEN` | Токен от @BotFather |
   | `ADMIN_TG_IDS` | Telegram-ID администраторов через запятую |
   | `BACKUP_PASSWORD` | Пароль шифрования бэкапов, не короче 12 символов |
   | `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` | Языковая модель — понадобится с части 9 |
   | `LLM_MONTHLY_BUDGET_USD` | Необязательный, по умолчанию 5 |
   | `TELEGRAM_PROXY` | Необязательный, если хостер начнёт блокировать Telegram |

4. Слить первый pull request. Ручные сценарии GitHub показывает только после того, как они попали в `main`,
   поэтому первая автоматическая «Выкладка» остановится на шаге «Подключение к серверу» с подсказкой — это ожидаемо.
5. Actions → «Настроить сервер» → Run workflow. Дождаться зелёного результата и удалить секрет `SERVER_ROOT_PASSWORD`.
6. Actions → «Выкладка» → Run workflow (ветка `main`). В Telegram придёт «✅ Версия … выложена».
7. Написать боту `/start`: владелец из `ADMIN_TG_IDS` проходит анкету и становится администратором.
   Близких он приглашает ссылкой: «☰ Ещё» → «🛠 Админ» → «🎟 Приглашения».

Дальше каждое слияние в `main` выкладывается само после зелёной «Проверки».

## Сценарии GitHub Actions

| Сценарий | Когда | Что делает |
|---|---|---|
| «Настроить сервер» (`bootstrap`) | Вручную, один раз | Обновления безопасности, файрвол (только SSH), подкачка 1 ГБ, Docker, пользователь `deploy`, отключение входа по паролю и под root. Можно запускать повторно |
| «Проверка» (`ci`) | Каждый pull request и коммит в `main` | Линтер, тесты, покрытие, миграции, пробный запуск, поиск секретов |
| «Выкладка» (`deploy`) | После «Проверки» на `main` или вручную | Образ в ghcr.io, проверка настроек, бэкап, миграции, запуск, проверка здоровья, автоматический откат |
| «Откат» (`rollback`) | Вручную | Возврат на одну из 3 последних версий |
| «Бот жив?» (`healthcheck`) | Раз в час | Проверка бота, диска и памяти; перезапуск и оповещение при сбое |
| «Очистить сервер» (`cleanup`) | Вручную | Удаление старых образов, кэша Docker и временных файлов |

На сервере хранятся только текущий и предыдущий образ бота, одна последняя копия базы
и логи не больше 50 МБ (раздел 7, «Место на диске»).

## Разработка

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
DATA_DIR=./data python -m habit_bot.ops migrate
pytest --cov
ruff check . && mypy habit_bot && lint-imports
python scripts/gen_error_table.py   # обновить таблицу ошибок ниже после правки каталога
```
