# Изменения

## 0.2.0 — часть 2: общий каркас диалогов

- Разбор ввода одной общей функцией (`kernel/domain/parsing.py`): числа с точкой и запятой, границы с подсказкой
  «может, лишняя цифра?», время «5:45», «5.45», «28.40», «1:02:03» или одним числом, даты «20.10», «20.10.2026»,
  «вчера», запрет будущих дат, логический день с границей 04:00. Показ чисел с запятой (`formatting.py`).
- Коды ошибок `INPUT-NUMBER`, `INPUT-RANGE`, `INPUT-TIME`, `INPUT-DATE`, `INPUT-FUTURE`, `UI-STALE`, `ACCESS-FOREIGN`.
  Ошибка ввода не сбрасывает диалог.
- Состояния ввода хранятся в базе (`DialogState`, миграция `0002_dialog_states`) и переживают перезапуск.
  Ключ — пользователь бота, а не Telegram-ID.
- Сброс незаконченного ввода через 15 минут без действий: при следующем действии, раз в минуту и при старте;
  без сообщения пользователю. Тренировка — 3 часа, анкета не сбрасывается (области на будущее).
- «✕ Отмена», слово «отмена» и `/cancel`. Переход в раздел меню закрывает незаконченный ввод.
- Кнопки несут владельца и номер ввода: устаревшая кнопка — «Это меню устарело» и главное меню,
  чужая или подменённая — отказ, ничего не меняется. Апдейты одного пользователя обрабатываются по очереди.
- Главное меню (Еда, Зарядка, Тренировка, Привычки, Итоги, Ещё) и «Ещё» (Другой день, Текстом, Выходной,
  Настройки, у администратора — Админ). Разделы отвечают «скоро» с номером части плана.
- `/check` — проверка ввода в три шага без записи. Фоновые задачи (`JobSpec`) в ядре.

## 0.1.2

- Документы проекта — требования, архитектура, диаграммы, ход разработки — лежат в `docs/`
  и обновляются после каждой части (правило в `CLAUDE.md`).
- Слияние, в котором изменились только документы (`docs/`, `*.md`), проходит «Проверку», но бота не перевыкладывает.

## 0.1.1

- Ручная «Выкладка» проверяет результат тестов на коммите, а не итог всего запуска «Проверки»:
  раньше она отказывала, если в том запуске упала автоматическая выкладка при зелёных тестах.

## 0.1.0 — часть 1: каркас, CI/CD, ошибки и первый администратор

- Структура проекта по архитектуре: ядро, платформа, Telegram-канал, модуль `users`; границы проверяет import-linter.
- Настройки из `.env` с проверкой всех полей сразу и полным списком проблем (коды `CFG-*`).
- База SQLite (WAL) и миграции Alembic: пользователи, способы входа (`Identity`), ключи повторов,
  оповещения администратору.
- Каталог ошибок с кодами, тексты для пользователя и администратора, коды инцидентов `E-xxxx`,
  склейка одинаковых оповещений за час; таблица «Что делать при ошибке» в README собирается из каталога.
- Структурированные JSON-логи без Telegram-ID: 14 дней, не больше 50 МБ.
- `/start`: администратор из `ADMIN_TG_IDS` регистрируется без приглашения, остальным — «Бот доступен по приглашению»;
  роль администратора пересчитывается при каждом запуске.
- Проверка здоровья (`python -m habit_bot.health`) и служебные команды (`python -m habit_bot.ops`):
  бэкап с одной последней копией, восстановление, миграции, тексты оповещений.
- Dockerfile, docker-compose и сценарии GitHub Actions: «Настроить сервер», «Проверка», «Выкладка»,
  «Откат», «Бот жив?», «Очистить сервер». На сервере — текущий и предыдущий образ и одна копия базы.
