# Ход разработки habit-bot

Репозиторий: `egorkudd/habit-bot` (приватный, защита `main` не включается — требования, ред. 10).
Бот в Telegram: @daily_habbit_bot. Сервер: HOSTKEY, Ubuntu 24.04.5, Docker 29.1.3.
Все части ведутся в одной сессии по очереди; следующая — после приёмки предыдущей владельцем.
После каждой части все документы (требования, архитектура, диаграммы, этот отчёт) обновляются
и выгружаются в папку `docs/` репозитория — правило в `CLAUDE.md` и в разделе 8.1 требований.

## Часть 1 — каркас, CI/CD, ошибки и первый администратор — ✅ ПРИНЯТА (03.11.2026)

На сервере версия 0.1.1. PR #1 (часть 1) и PR #2 (ручная выкладка проверяет задание «Проверка», а не итог запуска) слиты.
Приёмка владельцем: `/start` от владельца → приветствие администратора; от другого аккаунта → «Бот доступен по приглашению».
Выкладка 0.1.1 прошла автоматически после слияния: бэкап существующей базы (52 КБ, одна копия), миграции, запуск, проверка здоровья, оповещение в Telegram.

Что сделано:
- Ядро: настройки с полным списком `CFG-*`, SQLite + Alembic (`0001_initial`: users, identities, idempotency_keys, admin_alerts), User/Identity/Actor, ключи повторов, JSON-логи (14 дней, ≤ 50 МБ), реестры модулей и каналов, EventBus, UnitOfWork, UserScopedRepository, VersionedMixin.
- Каталог ошибок (`habit_bot/kernel/errors/catalog.py`), коды `E-xxxx`, склейка оповещений за час, таблица в README из каталога.
- Telegram-канал (ErrorMiddleware, уведомления), модуль `users`: `/start`, регистрация админа по `ADMIN_TG_IDS`, синхронизация ролей при старте.
- `python -m habit_bot.health` (лёгкая/полная проверка), `python -m habit_bot.ops` (check-config, migrate, backup/restore с одной копией, render текстов).
- Docker, compose, `deploy/remote.sh` (deploy/rollback/health/cleanup), сценарии bootstrap, ci, deploy, rollback, healthcheck, cleanup.
- CI: ruff 0.16.9, mypy 1.13, import-linter (4 контракта), shellcheck, 82 модульных + 32 интеграционных теста, покрытие 98% (домен 100%), миграции + `alembic check`, пробный запуск с поддельным Bot API, gitleaks.

Решения и находки по ходу:
- В окружении Claude закрыт PyPI — полный прогон тестов идёт только в GitHub Actions.
- Ручные сценарии GitHub доступны только из `main`: порядок — слияние → «Настроить сервер» → «Выкладка».
- Проверка настроек при выкладке сработала на деле: поймала короткий `BACKUP_PASSWORD` (CFG-BACKUP) до остановки бота.
- Оповещения в Telegram доходят после того, как владелец написал боту `/start`.
- Очистка старых образов в ghcr.io отрабатывает без ошибок — проверить, что реально удаляет, после 4-й выкладки.
- На vm.pico свободно ~260–275 МБ оперативной памяти при работающем боте (диск занят на 10%) — следить с ростом функций (вариант — vm.nano).
- «Бот жив?» на реальном сервере вручную ещё не запускался — первый плановый запуск раз в час покажет.

## Часть 2 — общий каркас диалогов — слита и выложена (04.11.2026, PR #4), ждёт проверки в Telegram

Владелец разрешил слить часть 2 после зелёных тестов и сразу начать часть 3. Версия 0.2.0, PR #4.
Проверка в Telegram — по чек-листу из PR #4; итог отметить здесь.

Что сделано:
- `kernel/domain/parsing.py` и `formatting.py`: числа с точкой и запятой, границы с подсказкой «лишняя цифра?»,
  время «5:45» / «5.45» / «28.40» / «1:02:03» / одним числом (секунды или минуты), даты «20.10», «20.10.2026», «вчера»,
  запрет будущего, логический день с границей 04:00; показ «77,5», «2 340», «5:45», «24.10».
- Коды `INPUT-NUMBER`, `INPUT-RANGE`, `INPUT-TIME`, `INPUT-DATE`, `INPUT-FUTURE`, `UI-STALE` и новый `ACCESS-FOREIGN`
  (внесён в требования, раздел 7.4.1).
- `DialogState` (миграция `0002_dialog_states`), `DialogStore`, `DbFsmStorage` — хранилище aiogram в базе по user_id бота.
- `ActivityMiddleware`: сброс просроченного ввода и продление при каждом действии; апдейты одного пользователя по очереди.
  Фоновая задача раз в минуту и при старте (`kernel/jobs.py`, `JobSpec`).
- `CallbackGuardMiddleware`: кнопки несут владельца `o` и номер ввода `t`; чужая — `ACCESS-FOREIGN`, устаревшая — `UI-STALE`.
- Отмена: кнопка «✕ Отмена», слово «отмена», `/cancel`. Главное меню и «Ещё» с ответом «скоро» и номером части.
- `/check` — проверка ввода в три шага без записи.
- Тесты: 209 (158 модульных + 51 интеграционный), покрытие 98%, домен 100%.

Решения и находки:
- Встроенное хранилище aiogram выключено (`disable_fsm=True`), `state` и `raw_state` кладёт `ActivityMiddleware` —
  так ключ строится по пользователю бота, а не по Telegram-ID.
- Номер ввода (`token`) — случайное число в строке `DialogState`. Новый ввод (`start_dialog`) получает новый номер,
  поэтому кнопки прошлого ввода устаревают сразу, а не только через 15 минут.
- Переход в раздел главного меню закрывает незаконченный ввод — иначе «🍽 Еда» принималось бы за ответ на вопрос.
- Модуль, подключая раздел, вызывает `menu.mark_ready(key)` и обрабатывает кнопку своим роутером.
- Для `workout` (часть 8) к сбросу добавится автозавершение тренировки, для `other_day` (часть 4) — отметка
  для «📅 Нет, за 24.10». Сейчас просроченные строки просто удаляются.
- Часовой пояс — `ZoneInfo("Europe/Moscow")`, в образ добавлен пакет `tzdata`.

## Часть 3 — регистрация и профиль — слита и выложена (04.11.2026, PR #5, версия 0.3.0), ждёт проверки в Telegram

Версия 0.3.0. «Проверка» зелёная: 256 тестов, покрытие 97,8%, домен 100%.

Что сделано:
- Приглашения (создать на 1/3/5/10 человек, срок 1/7/30 дней или без срока, список, отозвать), вход по ссылке
  `/start КОД`; коды `ACCESS-INVITE-EXPIRED`, `ACCESS-BLOCKED`.
- Анкета 12 шагов с «← Назад», «Заполнить позже» на шагах 10–12, продолжение с того же шага (область `onboarding`
  не сбрасывается). Отмена и `/start` во время анкеты повторяют текущий вопрос.
- КБЖУ (4.1): пример владельца 2800/160/80/360 и женщины 2050/110/55/280 — в тестах; ограничения снижения,
  предупреждения про углеводы; ручные КБЖУ с проверкой расхождения 5% (`INPUT-KBJU`).
- Город (4.12): кнопки, нормализация, синонимы, Open-Meteo с регионами, «Масква» → «Может, Москва?», работа без сервиса;
  кэш 30 дней в `source_cache`. Ответы геокодера в тестах — записанные.
- «Настройки»: профиль с кнопкой на каждое поле, пересчёт КБЖУ, история целей, цели вручную, удаление аккаунта.
- Изоляция: B не видит профиль и цели A, подменённая кнопка — отказ.

Решения и находки:
- Пустое значение в данных кнопки aiogram распаковывает как `None` — поле `v` у кнопок модуля необязательное.
  Символ «:» в значении кнопки запрещён (разделитель) — у приглашений «5_7».
- Удаление аккаунта стирает строки во всех таблицах с колонкой `user_id` — новые модули подключаются автоматически.
- Последний администратор = в `ADMIN_TG_IDS` нет другого ID (требование 3.0).
- Стартовый набор из анкеты хранится в профиле (`starter_kit`) и будет применён модулями частей 5–8.
- «Раз в год предложить пересчитать цели» — вместе с уведомлениями (v2).
- В окружении Claude теперь можно гонять интеграционные тесты локально (библиотеки из исходников GitHub);
  покрытие локально не считается точно — его даёт CI.
- Покрытие в CI теряло строки после обращений к базе: добавлено `concurrency = ["greenlet", "thread"]`.

## Часть 4 — дата записи и дни — слита и выложена (04.11.2026, PR #6, версия 0.4.0), ждёт проверки в Telegram

Версия 0.4.0. «Проверка» зелёная: 272 теста, покрытие 97,8%, домен 100%.

Что сделано:
- Логический день по времени сообщения (граница 04:00); `ActivityMiddleware` даёт обработчикам `today` и `record_day`;
  ввод помнит дату начала (`start_dialog(..., day)`): 03:58 → 04:02 остаётся в 24.10.
- «Другой день»: быстрые кнопки, календарь, ввод даты, запрет будущего, подтверждение старше 30 дней,
  «Вернуться к сегодня» на любом шаге (с вопросом при незаконченном вводе), отмена, сброс через 15 минут.
- «🛌 Выходной» (`days_status`), карточка дня (каркас), перенос «📅 На вчера» через реестр `EntryMover`.
- Настройка главного экрана (`users_profile.home_buttons`), миграция `0004_days`.

Решения и находки:
- После сброса «Другого дня» остаётся отметка `lost_day` на 12 часов — по ней часть 5 покажет «📅 Нет, за 24.10».
- «Перенести на дату» из «Записей дня» и сами записи — с части 5 (сейчас переносить нечего; механизм проверен
  на тестовом разделе).
- Роутер дней подключается первым, чтобы «Вернуться к сегодня» работало даже посреди чужого ввода.
- По умолчанию включены все модули — новые части не требуют менять секрет `ENABLED_MODULES`.
